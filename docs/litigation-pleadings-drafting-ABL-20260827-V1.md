# 起诉状、答辩状与上诉状起草教程

> 诉讼实战系列（七）｜适用：AI智能体（事实提取 + 金额试算 + 法条核验 + 模板复用）｜2026-08-27
> 用途：三类核心诉讼文书的 AI 辅助起草——以更优模板为基准，AI 做事实填充与调整完善。

## 一、它能解决什么问题

文书起草的三大耗时点：**从材料里捞事实、算清请求金额、核对外部依据**。AI 把这三件事接走，律师专注策略性表述与最终审定。

## 二、输入材料

- 案件材料：【路径】（合同、履行凭证、催告函、对账记录等——接系列六的证据要素登记表更高效）
- 我方立场与诉请意向：【描述】
- 管辖依据：【合同管辖条款或法定管辖分析】
- 本所其他项目的同类文书模板：【路径】（**优先使用，必需项**）

## 三、AI智能体能力配置

| 环节 | 用什么 |
| --- | --- |
| 事实要素提取 | 主对话（时间轴抽取）；扫描件 本地 OCR |
| 金额试算 | 主对话（分段计算表） |
| 法条/管辖核验 | 法规核验子代理 → 北大法宝 MCP 逐字核验 |
| 诉请写法参考 | 元典/北大法宝类案（同案由诉请表述与获支持口径） |
| 文书成稿 | Word 文档生成能力 + 模板复用 |
| 上诉期盯守 | AI智能体定时任务（判决送达日起 15 日，届满前 7 日/3 日两级提醒） |

## 四、标准工作流与提示词模板

### 第一步：事实要素与时间轴提取

```text
读取【案件材料】，输出：
1. 案件事实时间轴：合同签订—履行节点—违约事件—催告—损失发生的完整时序
   （每项附证据编号，接证据要素登记表）；
2. 违约/侵权情形归纳：每一项对应的事实与证据；
3. 主体信息表：各方名称、统一社会信用代码/身份证号、法定代表人、住所
   （工商信息经企查查/天眼查核对登记现状）。
先输出让我确认，再进入起草。
```

### 第二步：诉讼请求金额试算（核心）

```text
就我方意向诉请【描述】，输出金额试算表：
1. 本金：构成明细与依据；
2. 利息：起算日、利率口径（合同约定/LPR）、分段计算过程，算至【预计起诉日】；
3. 违约金：合同条款引用，对照司法调整尺度（类案调减情况检索）给出风险提示；
4. 其他费用（保全费、担保费等可主张项）。
要求：完整列出每一步算式备查；无法确定的参数（如实际清偿日）用【】占位并说明取值口径。
```

### 第三步：管辖与程序核验

```text
核验本案程序要点并逐项回复：
1. 管辖：合同管辖条款原文引用并判断效力；无约定的法定管辖分析；
2. 主管：是否有仲裁条款（逐份合同检查争议解决条款）；
3. 诉讼时效：起算、中断事由与剩余期间；
4. 主体适格：被告是否适格、是否需列共同被告（如担保人）。
上述涉及法条的，经北大法宝核验后引用，标注条文号与核验状态。
```

### 第四步：文书起草（模板复用，核心）

```text
起草【起诉状/答辩状/上诉状】：
【优先且必需】以我提供的其他项目更优模板【路径】为基准：
- 起诉状：仅替换当事人段、诉讼请求（引用第二步试算）、事实与理由
  （按模板行文风格组织，时间轴为骨、证据编号为注）；
- 答辩状：针对【对方起诉状路径】逐项答辩，模板的答辩结构保留；
- 上诉状：针对【一审判决书路径】逐项列"原审认定—上诉理由—法律依据"，
  上诉请求与一审诉请差异单独说明；
保留模板的格式、编号、签署页；输出修改说明（基于模板改了哪些、新增哪些）。
法条引用一律先经北大法宝核验。
```

### 第五步：交付自检

```text
成稿后自查并输出核验清单：
1. 当事人信息与登记信息一致；
2. 金额合计与试算表一致；
3. 每项事实陈述均有证据编号支撑（无证据的改为"待补"并提示）；
4. 全部法条条文号经核验；
5. 落款、日期、附件清单完整。
```

## 五、模板复用原则（本教程的核心方法）

**一律优先用律师认为更好的其他项目模板**：AI 只做事实填充、金额代入、口径调整（先长后短替换、最小必要修改、零残留质检——防其他项目信息残留，同《北交所三会文件批量起草提示词》映射表方法）；**无模板时不自行创造格式**，请律师提供或按律所统一格式新建。

## 六、红线

1. 金额计算 AI 列式、**律师复核**（利率口径、起算日最易错）；
2. 事实陈述不夸大、不写无证据支撑的内容；
3. 上诉状对一审认定的反驳须逐点对应判决书原文，不得笼统主张"认定事实错误"；
4. 上诉期 15 日用定时任务盯守，撤回上诉、缴费等节点一并提醒。
