# AI实战28｜监管问询怎么回复？先让Agent查历史审核案例，再搭当前项目的回复框架

任务清单明确以后，真正起草某一道问询前，我更建议先查历史审核案例，看看交易所在类似事实下到底追问什么，再搭当前项目的回复框架。

## 一、一次只处理一道问询

先重新拆解本题所有子问题，再读取当前项目与本题有关的材料，不要一口气把整份回复交给Agent。

## 二、先查案例再搭框架

通过内部IPO知识库、证券数据库MCP等检索同板块、近期、事实相似案例，先总结监管关注点，再比较当前项目与历史案例的相似与差异。

## 三、案例只能学论证路径

成功项目的回复不能直接复制。历史案例不能替代当前项目的事实、证据和律师核查。

## 四、事实先行，结论后置

框架可以围绕事实情况、原因、合规/处罚风险、经营影响、整改、核查程序和明确意见展开。材料不足的地方直接留待补。

## 直接复制的实战提示词

请处理问询函中的【具体题目】。先读取【当前项目相关材料】，重新拆出全部子问题；再通过【内部IPO知识库/证券数据库MCP】检索同板块、近期且事实相似的历史审核案例，先形成【监管关注点清单】和【历史案例—当前项目差异表】。在此基础上搭建本题回复框架，确保逐项覆盖所有子问题。历史案例只用于参考论证路径，不得替代当前事实；材料不足处标记【待补充/待确认】。框架经律师确认后，再起草已确认部分。

## 最后记住一句话

监管问询回复不是“找一份成功案例照着写”，而是：**先理解监管为什么问，再用当前项目自己的事实把问题答完。**
