# AI实战22｜客户给了案情和底稿，让Agent通过法律数据库MCP直接做类案检索报告

客户把案情、合同和证据交过来后，类案检索不应只靠浏览器关键词。接入法律数据库MCP后，可以让Agent先理解本案，再围绕真正争议点多轮检索并形成正式类案报告。

## 一、先读案情再定检索词

Agent先从客户材料提炼法律关系、争议焦点和需要裁判的问题，再设计关键词。否则很容易只按案由搜出大量表面相似案件。

## 二、检索要迭代

第一轮阅读案例后，继续提取法院常用裁判语言、相反观点和更精确事实词，再做第二轮搜索。

## 三、逐案核验基本信息

重点案例至少核对案号、法院、审级、裁判日期、关键事实、争议焦点、裁判理由和结果；同一案件有一审、二审、再审时尽量串起来。

## 四、不要用案例数量投票

十个支持案例不一定比一个高层级、事实高度相似案件更有价值。报告应解释本案和案例的相似点、差异点及差异是否影响结论。

## 直接复制的实战提示词

请先阅读【客户案情/诉辩材料/证据/已有分析】并提炼核心争议问题，再调用【法律数据库MCP】开展多轮类案检索。每轮根据已阅读案例补充关键词和裁判语言，同时查找支持与不支持我方的案件。重点案例逐案核验案号、法院、审级、日期、关键事实、争议焦点、裁判理由和结果，并比较与本案的相似点和差异点。最终生成【类案检索报告.docx】，不得用案例数量简单替代法律判断。

## 最后记住一句话

类案检索不是“找几个判决”，而是：**找到真正决定裁判结果的事实分界线。**
